# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`skewcal` measures a 3D printer's XY skew and X/Y scale (the target is a Prusa MINI+) by machine vision instead of calipers. A flat plate with a 9×9 grid of holes is printed, then scanned or photographed. The tool fits the hole centres and outputs the true X–Y angle. `skew_gcode.py` then corrects the skew as a PrusaSlicer post-processing script. Not a git repo.

## Commands

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt   # + pillow-heif for iPhone .HEIC
.venv/bin/python tests/run_tests.py      # end-to-end synthetic tests (~20 s); prints PASS/FAIL per case
python3 tests/test_gcode.py              # post-processor geometry test (stdlib only)
python3 tests/test_firmware.py           # Klipper/Marlin/RRF skew settings vs each firmware's transform (stdlib only)

.venv/bin/python skewcal.py photo A.HEIC B.HEIC [--span-x 174.0 --span-y 234.0] [--no-warp] [--focal-px F]
.venv/bin/python skewcal.py scan  S1.png S2.png [--dpi 600]
.venv/bin/python skewcal.py plate -o skewcal_plate.stl    # regenerates STL + .json
.venv/bin/python skewcal.py sheet --page letter|a4 [--dark]

.venv/bin/python tools/build_web.py      # rebuild web/ after changing any Python code (also fetches Pyodide, makes samples)
python3 tools/serve_web.py               # browser app at http://localhost:8765 (.claude/launch.json: skewcal-web)
```

`run_tests.py` is one script, not a pytest suite. To run a single case, comment out the other numbered sections or call `synth.render_*` and `cli.main([...])` yourself. Rendered test images go to `tests/_out/`. Real user photos and their outputs (`*_skewcal.jpg` overlays, `skewcal_report.{txt,json}`) are kept under `runs/<date>/`.

## Architecture

The pipeline, mostly in `skewcal/analyze.py`:

1. **Get a metric image.** All later stages work in "mm, y-up" coordinates via a `to_mm` callable.
   - **Scan:** the image comes from DPI, downsampled if very large.
   - **Photo:** `rectify_phone` detects the ArUco markers on the reference sheet (`sheet.py`) and fits a homography plus radial `k1` plus a marker "growth" term (ink spread). It then resamples the 140 mm window at 15 px/mm. It also estimates the camera distance D (EXIF focal length, or a Zhang single-view estimate) for the plate-thickness parallax scale correction.
2. **`detect_holes`.** Finds the largest dark (or light) component of plate size, then the holes enclosed in it, sorted into big and small by area. Centres are refined by intensity-weighted centroids. Hole centres, not edges, are used, so the result doesn't depend on hole size, flow or elephant's foot.
3. **Index the grid.** `index_grid` uses the three small marker holes: one X marker, and a Y pair spaced `y_pair_sep` apart (geometry in `plate.py`). It finds the origin and the X/Y axes and handles rotation and mirroring. If the markers can't be segmented (they often print partly closed), `index_grid_by_lattice` fits the lattice from the big holes alone. It then scores all 8 corner/axis assignments by image brightness at the predicted marker positions.
4. **`fit_affine`.** A robust linear least-squares fit of nominal → measured positions. With `warp=True` (photo mode default) it adds a plate-height model. The bowl/saddle terms z/D·q·(p−p̄) are shared between x and y, plus a free quadratic field per axis that absorbs the unknown camera nadir. Warp mostly biases scale, not the angle. The XY angle comes from `geometry_from_affine`, and the uncertainty is Monte-Carlo sampled from the full solution covariance.
5. **`combine` (90° reversal).** The scanner or paper sheet is never perfectly square. Images with the plate turned 90° *relative to the reference* flip the sign of that frame error (`frame_sign`), so a weighted fit solves θ_printer and the frame bias together. Scale anisotropy of the frame is separated the same way using `plate_x_along_frame_x`. Without a reversal the report prints a warning.

`skewcal.py` is a thin CLI: argument parsing, per-image loop, report text and JSON. It prints the PrusaSlicer post-processing line. `skew_gcode.py` must stay **standard-library only** because PrusaSlicer runs it with the system `/usr/bin/python3`. It maps commanded (x, y) through M⁻¹ about the bed centre (90, 90), where M = [[sx, sy·cos θ], [0, sy·sin θ]], and linearises G2/G3 arcs. It refuses binary G-code.

**Browser app (`web/`).** It runs the unchanged Python package in Pyodide inside a Web Worker (`worker.js` calls `web/py/bridge.py`). `py_bundle.js`, `assets/`, `samples/`, `sample_result.json` and `pyodide/` are generated by `tools/build_web.py`; edit the Python sources, not the bundle. `analyze_*(details=True, annotate_crop=True)` returns per-hole residuals and a cropped overlay for the charts. `index.html` has no doctype/head because it is written as a claude.ai Artifact body; `serve_web.py` adds the skeleton. claude.ai Artifacts can't host it: they refuse .zip/.whl files, which Pyodide needs. Any static host works.

`tests/synth.py` renders ground-truth images: scanner rotation, mirroring and frame error, and phone perspective, `k1`, paper skew, parallax height `h`, partly closed markers (`marker_scale`) and a cupped plate (`warp`). When changing analysis code, add or adjust a synthetic case that reproduces the real-photo problem before tuning it on real data.

## Conventions and gotchas

- `PlateSpec` (in `plate.py`) is the single source of plate geometry; the `plate` command's defaults are read from it. Marker holes are 2.4 mm since 2026-10-14 (2.0 mm before; they closed up on a modified printer). `skewcal_plate.json` must match the printed STL, and the analysis loads a custom one via `--plate`. The STL must be printed unrotated, with the origin hole at front-left.
- Sheet constants (`WINDOW_HALF`, `SPAN_X_NOMINAL`=174, `SPAN_Y_NOMINAL`=234, `ARUCO_DICT`) live in `sheet.py`. Changing them invalidates the PDFs already printed.
- **Breakaway cube** (`plate.build_cube`, `skewcal.py cube`):
  - It has four `PlateSpec.cube_wall()` walls (118 mm, straight holes, `wall=True`) in a pinwheel with 0.8 mm corner gaps bridged by overlapping tab boxes, plus the default plate as the floor.
  - Wall local x maps to +X (front/back) or +Y (left/right), and local y to +Z. `id_holes` (1 or 2) only label the walls.
  - The analysis is unchanged. `--plane xz|yz` relabels the report and the correction flag, and is required for walls.
  - `skew_gcode.py --xz-angle/--yz-angle` subtracts z·(ezx, ezy) from X/Y before the XY inverse, and adds X/Y to Z-only moves when a shear is active.
  - Within a reversal pair, a wall must be turned, not flipped and turned. That combination doesn't flip the frame-error sign.
- **Firmware output** (`skewcal/firmware.py`, `skewcal.py firmware`, and the Correct tab in `web/app.js`, which ports the same maths). Klipper and Marlin apply x−y·xy−z(xz−xy·yz), y−z·yz, so xy=cos θ, xz=ezx and yz=ezy/sin θ. RepRapFirmware's M556 adds the terms instead (X→tanXY, Y→tanYZ, Z→tanXZ), so the signs are negated, plus a cross term in tanXZ. Klipper gets the AC/BD/AD of a virtual 100 mm square. Keep the JS and Python versions identical.
- There are two photo references, the paper sheet (marker ids 0–58) and the tablet screen (ids 59–98, `SCREEN_*` in `sheet.py`). `rectify_phone` picks one from the detected ids. The screen layout is drawn by `web/app.js` from `web/screen_markers.json`, which `build_web.py` exports. Change both together.
- **Thin-rim plate.** `PlateSpec()` is the default thin-rim plate (rim 0.6, top_d 5.6); `PlateSpec.standard()` has straight holes.
  - `from_json` treats files without a `rim` field as standard, which keeps old plate files valid.
  - `feature_height(upside_down)` is the parallax height. The screen reference adds `SCREEN_GLASS_MM`.
  - In photo mode a mirrored plate is lying first-layer side up. `analyze_photo` then recomputes the parallax correction (`upside_down` in the result).
  - The web samples are standard-plate scans (`plate` in `samples/index.json`).
- Photo `correct_warp` defaults to `"auto"`: the bow model is kept only if the corner bow is > `BOW_MIN_MM` and > 3σ. The 3 mm "cup" seen in 1× photos at 22 cm was lens distortion, not a real bow.
- Hole detection is glare-robust. The plate region is closed at ~2 px/mm, candidates come from a local-contrast map, missing grid positions are predicted from the lattice, and centres come from an edge circle fit with per-ray thresholds (`_edge_circle`).
- Report quality signals:
  - **ref fit:** the sheet homography residual. Under about 100 µm is good. Higher means a wavy sheet or a blurry photo.
  - **fit rms:** the plate grid residual.
  - **plate corners vs centre:** the warp, in mm.
- Without `--span-x/--span-y`, absolute scale assumes the sheet printed at exactly 100%.
- Real-photo gotchas:
  - Images pasted into chat are resized to about 2000 px and lose EXIF, so ask for the original files.
  - Users often rotate the phone instead of turning the plate on the sheet, which means there is no reversal.
